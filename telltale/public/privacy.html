What this site does with your text

Short version: it analyses it inside one Node process on the server you're talking to, writes a copy into a JSON file on that same machine so the dashboard works, and sends it nowhere else. No model provider, no analytics, no third-party scripts, no cookies.

Deleting things

  • 1Delete one scan: the ✕ button in the dashboard's recent-scans table, or DELETE /api/scan/:id.
  • 2Delete everything: "Wipe history" on the dashboard, POST /api/clear, or delete the data/scans.json file.
  • 3Stop storing altogether: set STORE_SCANS=false and restart. Reports still work; nothing is written to disk.
  • 4Clear your local draft: "Clear" in the analyser, or your browser's site-data settings.

If you deploy this for other people

The default configuration keeps everyone's scans in one shared list, which is fine for a personal tool or an internal demo and wrong for a public service. Before you put this on a domain:

  • !Set STORE_SCANS=false if you don't want to hold other people's text at all — this is the honest default for a public deployment.
  • !Or keep storage but add authentication and per-user isolation before exposing the dashboard, since it lists every stored scan to anyone who visits /dashboard.
  • !Tell your users what you keep and for how long. A detector that quietly archives submitted writing is a different product from this one.
Built to be auditable: the storage layer is one readable file (src/store.js, ~180 lines) and the analyser is another (src/detector.js). Nothing here is a black box — including the privacy claims.
